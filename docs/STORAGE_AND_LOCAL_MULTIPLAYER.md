# OLS 0.4.0：存储位置、滚动优化与本地模组联机

## 把游戏数据放到其他磁盘

入口：「启动器设置 → 本地存储位置 → 更改存储位置」。可选择任意有足够空间且可读写的本地目录，例如 `D:\Games`、`E:\Minecraft`；启动器在其下创建专用的 `OLSData` 子目录。目录不强制放在C盘，也不需要移动EXE或重新下载所有游戏。

选择后显示源目录、目标目录、文件数与大小，点击「复制迁移并使用新位置」执行。迁移覆盖游戏版本、库、资源、模组、存档、Java、缓存、加密账号凭证、设置及自定义背景。每个文件复制后做SHA-256校验，保留空目录；全部成功后才原子更新位置索引。新下载、新实例及存档读写随后使用新位置，重启继续使用。

首次使用时可先设置位置，再下载游戏，避免大文件落在C盘。少量启动位置索引、Electron日志及官方网页登录缓存仍使用系统用户数据目录；选择新位置不会把这些系统管理的小文件一并搬走。

### 迁移前后

- 退出游戏、停止联机，等待安装/下载任务完成，同时关闭其他可能写入原目录的程序。迁移期间软件限制写操作，可在下载管理查看进度或取消；文件全部校验后的短暂位置索引提交步骤不可取消，避免把已切换的位置误报为取消。
- 目标OLSData必须不存在或为空，不会覆盖已有游戏目录。拒绝源/目标互相嵌套及符号链接，检查可用空间并保留64MB余量。
- 迁移采用复制，**旧目录完整保留为备份，不会自动释放旧盘空间**。确认重启、版本、存档及账号在新位置正常后，再自行清理旧备份。不要误删新目录。
- 如果取消/失败，仍使用原位置；目标可能保留带 `.ols-migration.json` 的不完整副本。保留原目录，重新选择另一个空目录重试；该副本不能当成完整备份。
- 位置索引保存在Electron系统用户数据目录的 `storage.json`。不要单独移动新数据目录或拔掉磁盘；下次启动若目标不可用会明确报错，不会默默回到C盘创建空白游戏库。重新连接原磁盘或恢复原路径后再启动。
- Microsoft/Sakura凭证仍使用本机系统加密。这是同一台电脑上的位置迁移，不是跨电脑账号迁移。
- 若指定的Java可执行文件原本就在旧OLS数据目录内，其路径会随迁移更新；外部Java路径保留。模组或私人脚本自行写死的绝对路径需要本人检查，启动器不会批量改写任意配置文本。
- 0.3及更早客户端不识别新位置索引，回退旧客户端可能打开旧备份。不要把旧备份误认为迁移后的最新存档。

## 本地模组也能开放好友世界

此前只要资源标为「本地」，就直接阻止房主开放。0.4.0取消这个拦截，改成「房主开放 → 好友选择已准备的本地实例 → 校验实际JAR → 加入」。**房主、好友客户端及好友服务端需要升级到0.4.0**。

房主仍使用「好友联机 → 开放我的世界」。自动开世界继续仅支持Fabric1.21.1；其他已支持实例可用已开放LAN模式。本地模组不要求转换为Modrinth项目。

房主发布前扫描实际mods目录中的启用JAR，包括手动放入但未登记为平台资源的文件。发送文件名、大小、SHA-512清单，不上传JAR或私人配置。好友列表显示「选择本地实例加入」。朋友需要事先通过双方约定的方式取得相同文件，在OLS导入/准备好游戏版本和Fabric版本都相同的实例。

加入窗口会重新读取所选实例的实际JAR，列出缺少/版本不同及多出的文件。一致才可加入；点击加入时后台再次校验。相同内容的JAR即使改名仍可通过，内容不同不会只因文件名相同而通过；`.disabled`不计入。OLS随包的LAN桥接按完整文件摘要豁免，不要求好友额外安装房主专用桥接。

当前最多校验512个启用JAR。严格比较全部启用模组，因此额外的客户端模组也会显示为多出；请自行准备一致的联机环境。配置、脚本、材质包、光影、世界数据不自动同步，摘要一致也不能代替真实游戏兼容性验收。不会自动从房主下载执行JAR，也不会覆盖好友原有模组来追求匹配。加入使用本人明确选择的实例，不在该实例内自动安装或替换私人模组。

全平台管理、文件未被手工改动的Modrinth环境继续自动准备独立好友实例。原版/Fabric以外的Forge、NeoForge、Quilt仍只支持既有本地识别查看，不因本轮改动获得启动支持。自动进入多人地址仍需要游戏本身支持Quick Play（通常1.20及以后），旧版本可在游戏内手动直连。

### 服务端升级

SQLite账号/好友表结构不变，停服备份后替换0.4.0服务程序并重启。新增房间schema2用于本地JAR清单，schema1平台房间兼容保留。旧服务端不支持此清单，会明确提示需要更新；旧客户端遇到新房间不能自动准备私人模组，应升级后使用。部署步骤见服务端DEPLOYMENT.md。

## 首页滚动

原创方块场景由SVG预渲染为2200×1360 PNG，避免在低性能设备滚动时处理复杂矢量内容；移除窗口底部重复的大幅景观层，仅保留首页主体场景及用户自定义背景。首页内容按实际数据变化缓存，后台进度通知由120ms调整为250ms，React将状态刷新作为低优先级更新。滚动容器/场景使用有限绘制区域与独立合成层。

本机做了SVG/PNG/PNG/SVG四段滚动短样本，记录在verification/scroll-benchmark.json。样本未复现超过25ms长帧，SVG与PNG之间没有可确认的帧率提升。因此这里只交付减少重绘/更新的实现及本机验证，不宣称已证实你那台电脑的卡顿根因或具体提升百分比。可继续使用「减少动画」降低动态效果。

## 验证边界

自动测试覆盖复制校验/取消/失败/目标覆盖/链接/空间/重启索引，以及本地房间发布、权限、文件差异、版本校验、加入时复检。桌面测试实际选择E盘路径、复制存档与加密凭证、重启并使用新路径；本地好友服务的真实HTTP流程通过。启动使用合成凭证与Java测试程序验证，不是真实Minecraft、微软账号或Sakura跨网游戏验收；未在两块物理磁盘之间进行硬件迁移测试。
