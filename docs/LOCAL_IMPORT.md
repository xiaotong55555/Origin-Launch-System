# OLS 0.2.0 本地游戏识别与导入

## 使用

打开「我的游戏 → 识别本地游戏 → 选择文件夹」。可以选择：

- `.minecraft` 游戏根目录，或包含它的启动器目录。
- `versions` 目录，或 `versions/<版本名>` 具体版本目录。
- 含 `.minecraft` 与 `mmc-pack.json` 的 MultiMC/Prism 类整合包实例。
- 仅含 `mods` 或 `saves` 的目录。这类目录会显示资源信息；不能确认游戏版本时不开放启动导入。

版本下拉框用于切换扫描到的多个版本。点击“模组 / 世界存档 / 光影 / 材质包”卡片查看详细清单。

## 识别信息

| 内容 | 读取结果 |
| --- | --- |
| 游戏 | 配置名称、Minecraft 基础版本、加载器及版本、实际内容路径、共享/隔离目录 |
| 模组 | 文件名、主要模组名称、ID、版本、声明的加载器、文件大小、停用后缀 |
| 存档 | `level.dat` 中的世界名、最后打开的游戏版本、模式、极限标记、最近游玩时间 |
| 光影/材质 | ZIP 或常见解压目录、文件名、大小、`pack.mcmeta` 描述与格式号 |
| 异常 | 元数据损坏、缺少基础配置、继承循环、无法确认版本、跳过链接等 |

Fabric、Forge、NeoForge、Quilt 和旧式 `mcmod.info` 的常见元数据均可读取。JAR 仅作为压缩包读取元数据，不执行其中代码。单个 JAR 中存在多个模组时，清单显示主要条目。

模组的“启用/停用”按磁盘文件后缀识别；它不等于游戏运行时已经加载成功。材质包和光影是否在游戏中选择启用，仍以游戏设置为准。

## 复制导入

目前可复制导入原版/Fabric 的现代版本（1.13 起）；Forge、NeoForge、Quilt 仅展示识别结果。不能确认基础版本的目录也仅可查看，避免把自定义名字当成可下载的官方版本。

点击「复制导入选中版本」后：

1. 新建 OLS 独立实例，复制选中的实际游戏内容目录中的 `mods`、`saves`、`resourcepacks`、`shaderpacks`、`config`、`defaultconfigs`、`kubejs`、`scripts`，以及常见游戏选项和服务器列表文件。
2. 不复制启动器账号文件、启动脚本、凭证或存档 `session.lock`。扫描与复制不改动原目录；含文件系统链接的内容会拒绝复制。
3. `.disable`、`.old` 等停用后缀在副本中统一为 `.disabled`，原文件名保留。
4. 按官方清单校验并复用本地客户端、库和资源缓存；只补齐不能复用的文件。复制不是硬链接，后续修改 OLS 实例不会修改原文件。
5. 内容复制、运行文件校验和 Java 准备完成后才标记为可启动。正版游戏账号要求与新安装实例相同。

扫描完全离线。复制本地内容也不需要上传文件；正式补齐版本/加载器/依赖仍需要联网。请先退出原游戏再复制存档，以免复制过程中世界继续变化。

## 取消与失败

取消或复制失败时保留未完成实例，可在「下载管理」重试原任务。内容尚未复制完整时，普通“校验修复”不会绕过该阶段。重启 OLS 后中断的复制会标为失败，可重新扫描同一目录再次导入。

若内容已复制完成、仅官方依赖阶段因网络失败，则可以重试任务或在游戏库执行校验修复。此时保留已复制的模组、配置和存档，不会当成完整可启动实例。

## 好友联机边界

本地识别的模组标为“本地”，不会把它们的文件名伪装为 Modrinth 项目 ID，也不会自动上传给朋友。0.4.0起可以直接开放本地模组好友世界，朋友选择已准备好的相同版本实例并按JAR摘要校验后加入，不要求转为Modrinth版本；双方客户端及好友服务端需升级到0.4.0。模组文件仍不自动分发，详见 STORAGE_AND_LOCAL_MULTIPLAYER.md。安装同一模组的 Modrinth 版本时，会按真实模组 ID/文件名替换原本地条目并备份旧副本。

这不改变原有 Fabric 1.21.1 自动开世界桥接的版本范围。

## 实现

- `electron/core/local-scan.ts`：有界目录发现、版本继承、加载器/资源元数据识别。
- `electron/core/world-info.ts`：有大小、深度、数量限制的 Java NBT 摘要读取。
- `electron/core/local-import.ts`：安全复制、停用后缀处理、资源摘要、官方缓存复用。
- `src/LocalGameImport.tsx`：选择目录、版本切换、分类详情、复制导入。
- `scanLocal` IPC 只打开系统目录选择器；导入 IPC 只接受主进程保留的短期扫描 ID，界面不能提交任意磁盘路径。

## 验证

新增自动测试覆盖目录结构、继承/版本判定、元数据、NBT、离线只读、复制边界、停用状态、链接拒绝、摘要缓存复用和模拟 HTTP 下的安装收尾。桌面测试验证了选择目录、两个版本切换、双主题详情、实际复制和预期离线恢复。

桌面验收使用明确的合成测试目录，未读取或修改用户现有游戏实例，未将合成模组称为真实可运行模组，也未启动实际游戏。具体测试数量和记录见 `VERIFICATION.md`。
